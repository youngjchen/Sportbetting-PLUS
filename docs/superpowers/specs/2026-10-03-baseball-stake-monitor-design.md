# 四聯盟 Stake 盤口監控設計

日期：2026-10-03

## 1. 目標

在既有棒球大頁面一次監控 MLB、NPB、KBO、CPBL，不要求使用者逐場點進比賽頁。每張比賽卡片要能直接看見：

- Stake 目前讓分方、盤口與賠率。
- 讓分方是否曾經對調、對調次數、最近一次對調時間與方向。
- 大小分基準線，並在不覆蓋人工輸入的前提下自動填入卡片。
- 資料最後更新時間，以及正常、部分缺漏、過期或已凍結等狀態。

系統每五分鐘觀測一次。比賽開打前最後三十秒內的變化不列入歷史，也不改變最終讓分方或大小分；開賽後完全停止更新，保留最後一筆合格的賽前資料。這可用來回看使用者睡覺期間是否發生讓分方變動。

## 2. 非目標

- 不以 OddsPortal 作為即時盤口來源。
- 不以 Bet365 補成 Stake 賠率，也不把 Bet365 的變動記為 Stake 變動。
- 不要求使用者逐場開啟 Stake 或 BetExplorer 頁面；個別賽事頁如有需要，由後端自動存取。
- 不改動既有 Bet365、台彩、明牌或結算資料的語義；本功能是獨立的 Stake 監控軸。
- 首版不刪除舊的 `stake_odds.json`、`stake-odds-addon.js` 或名稱仍帶 `oddsportal` 的歷史整合，待新管線驗證穩定後再另案清理。

## 3. 核准決策

1. 使用一條四聯盟共用的收集管線，而不是四條彼此重複的工作流。
2. 資料寫入單一標準化檔案 `data/baseball_stake_odds.json`；每個聯盟有獨立健康狀態，單一聯盟失敗不得清空其他聯盟。
3. 前端以一支 add-on 模組 `baseball-stake-integration.js` 接入既有 `index.html`，所有資訊直接顯示在四聯盟共用的大頁面。
4. 賽程以現有官方賽程資料 `data/pregame_data.json` 為白名單；Stake 回傳但無法精確對應官方賽事的項目一律不寫入，例如冠軍、分區或系列賽期貨。
5. MLB 的 Stake 讓分盤若在開賽前變成 ±1，畫面與卡片仍標準化為 ±1.5；讓分方向以 Stake 官方 ±1 的正負號判斷，±1.5 的兩側賠率只取 BetExplorer 同場比賽中 `Stake.com` 那一列。
6. BetExplorer 找不到有效的 `Stake.com` ±1.5 列時，不採用 Bet365 或其他莊家替代；保留最後有效資料並標示等待更新或過期。

## 4. 架構與檔案邊界

### 後端收集器

新增四聯盟共用收集器，沿用現有 NHL Stake 管線已驗證的官方頁面存取、非同步 Scrapling sidecar 與 Cloudflare 容錯方式，但棒球市場解析須獨立實作，不直接套用冰球市場名稱。

每輪流程：

1. 載入 `data/pregame_data.json`，建立近期未開賽賽事白名單。
2. 分別讀取四個 Stake 官方聯盟頁與必要的個別賽事市場。
3. 將候選賽事與官方白名單撮合，排除期貨、錯誤聯盟與無法確定的賽事。
4. 解析獨贏、讓分與大小分；本功能主要使用讓分與大小分，獨贏保留作核對證據。
5. 遇到 MLB ±1 特例時，再讀取 BetExplorer 同場賽事並鎖定 `Stake.com` 的 ±1.5 列。
6. 套用三十秒截止規則、去重、換邊判定及每場歷史合併。
7. 原子式更新 `data/baseball_stake_odds.json`，不得因單一頁面失敗寫入空集合。

### GitHub Actions

新增或整併為一條長時間循環的棒球 Stake 工作流，遵循本專案既有模式：單次執行內每五分鐘收集、`WORKFLOW_PAT` 自我接棒，cron 僅作斷鏈備援。工作流只提交實際有變動的標準化資料檔。

### 前端

新增 `baseball-stake-integration.js`，由 `index.html` 載入並帶版本查詢字串。模組只負責：

- 讀取標準化 JSON。
- 以官方賽事鍵找到既有卡片。
- 呈現 Stake 監控狀態與歷史摘要。
- 在符合自動擁有權規則時更新讓分方與大小分基準線。

既有卡片建立、儲存、同步及結算流程仍由 `index.html` 原有邏輯負責。

## 5. 資料來源與優先序

### 官方賽程白名單

`data/pregame_data.json` 是四聯盟賽事身分的權威來源。Stake 的聯盟頁只能提供盤口候選，不能單獨創造比賽卡片。

### Stake 官方盤口

使用以下聯盟路徑作為主要盤口來源：

- MLB：Stake 美國職棒大聯盟頁。
- NPB：`/sports/baseball/japan/npb`
- KBO：`/sports/baseball/republic-of-korea/kbo-league`
- CPBL：`/sports/baseball/chinese-taipei/cpbl`

正常情況下，讓分方向、原始盤口、兩側賠率與大小分均以 Stake 官方資料為準。

### BetExplorer 特例

BetExplorer 只處理 MLB 原始讓分盤為 ±1 的特例：

- Stake 官方資料決定讓分方與 `rawLine = 1`。
- 對外顯示及自動填卡使用 `canonicalLine = 1.5`。
- `canonicalOdds` 必須來自 BetExplorer 同場的 `Stake.com` ±1.5 列。
- Bet365、其他莊家平均值或最接近的盤口都不得替代。

來源互相矛盾時不猜測：保留上一筆完整資料，記錄錯誤原因並把該場標成部分缺漏。

## 6. 賽事撮合與期貨排除

每個 Stake 候選項目必須同時符合：

- 聯盟相同。
- 主客隊經別名正規化後完全對應。
- 比賽日期與預定時間落在允許誤差內。
- 雙重賽能以官方比賽識別碼、場次或開賽時間唯一區分。
- 官方賽程狀態為尚未開賽。

隊名別名放在明確的聯盟對照表並有測試覆蓋；新增隊伍時只需補對照表，不得因單一未知隊名讓整個聯盟資料歸零。

以下候選一律排除：冠軍、分區冠軍、系列賽勝負、晉級、球季特別盤、無唯一主客隊或無法對應官方比賽識別碼的項目。

## 7. 觀測、凍結與換邊規則

### 時間判定

每一筆資料使用完成解析時的 UTC 時間作為 `observedAt`，不得沿用抓取開始時間。只有在下式成立時才接受：

`observedAt <= scheduledStart - 30 秒`

因此即使請求在截止前發出，只要解析完成時已進入最後三十秒，該筆仍須捨棄。到達截止時間後，把最後一筆合格資料標為 `frozen`；開賽後不再追加歷史。

### 去重

讓分方、原始盤口、標準盤口、兩側賠率及大小分都沒有改變時，不新增歷史節點，只更新管線健康時間。賠率或盤口改變可以留下歷史，但只有讓分方由主隊變客隊或由客隊變主隊才計入 `favoriteFlipCount`。

### 換邊歷史

每次換邊保留：

- 換邊前與換邊後的讓分方。
- 原始及標準化盤口。
- 當時兩側賠率與大小分。
- 每個欄位的來源。
- 合格觀測時間。

畫面顯示最近一次換邊方向與時間，並可在同一張卡片展開完整歷史；不需離開大頁面或開啟外站。

## 9. 大頁面顯示與自動填卡

每張比賽卡片增加一列緊湊狀態，最少包含：

- `Stake：主讓 1.5（1.95）` 或 `Stake：客讓 1.5（1.91）`。
- `換邊 1 次｜最近 客→主 06:15`；未換邊則顯示穩定狀態。
- `大小 8.5`。
- 最後更新時間與狀態圖示。

資訊直接出現在 MLB、NPB、KBO、CPBL 共用的大頁面。完整歷史可在卡片內展開，但核心判斷不得依賴展開或逐場外連。

### 自動擁有權

為避免自動資料覆蓋使用者操作，每張卡片新增兩個持久化狀態：

- `stakeAutoHandicap`：目前讓分方是否仍由 Stake 自動維護。
- `stakeAutoTotal`：目前大小分基準線是否仍由 Stake 自動維護。

規則如下：

1. 新建卡片或欄位為空時，可由有效 Stake 資料取得自動擁有權並填值。
2. 既有卡片若欄位已有值但沒有自動擁有權標記，視為人工資料，不自動覆蓋。
3. 使用者按讓分對調鍵後，立即把 `stakeAutoHandicap` 設為 `false`；後續只顯示監控差異，不改卡片方向。
4. 使用者手動編輯大小分後，立即把 `stakeAutoTotal` 設為 `false`；後續只顯示監控值，不覆蓋輸入。
5. 提供小型「恢復自動」控制，可分別重新啟用讓分或大小分同步。
6. 雲端盤面同步須保存這兩個狀態，避免跨裝置後又覆蓋人工選擇。

## 10. 錯誤、過期與健康狀態

- `ok`：本輪成功取得並解析。
- `partial`：部分賽事或市場缺漏，但保留其他有效資料。
- `stale`：距離該聯盟最近成功更新超過三十分鐘。
- `frozen`：已到賽前三十秒截止點，保留最後合格資料。
- `unmatched`：Stake 候選無法唯一對應官方賽事，不套用卡片。

單場失敗保留該場最後有效快照；單一聯盟失敗保留該聯盟舊資料；整輪失敗不得寫出空 `matches`。前端必須區分「真的沒有盤」與「抓取失敗」，避免把故障顯示成沒有比賽。

## 11. 相容與遷移

1. 新管線先以獨立資料檔和 add-on 上線，不改寫 `data/odds_log.json`、`data/pregame_data.json` 或既有明牌檔。
2. 舊的 BetExplorer 每日摘要仍可服務既有收盤用途，但新監控不得從舊的 `data/oddsportal_summary.json` 推導即時讓分方。
3. 舊卡片第一次載入時遵守人工資料保護規則；不做全量覆寫。
4. add-on 上線時同步更新 `index.html` 的 `?v=`，避免瀏覽器快取舊版。
5. 新管線連續穩定運作並通過實際比賽驗證後，才評估移除重複的舊 Stake 模組。

## 12. 測試與驗收標準

### 後端測試

- 四聯盟官方路徑可各自成功解析；任一聯盟失敗不影響其他三個。
- 新隊名未知時只標記該場無法撮合，不清空聯盟。
- 期貨候選即使出現在 MLB 聯盟頁也會被官方賽程白名單排除。
- 雙重賽以官方識別碼或時間正確區分。
- 相同觀測不重複寫歷史；只有主客讓分方互換才增加換邊次數。
- 解析完成時間落在開賽前 30 秒內或開賽後時，該筆被拒絕。
- MLB ±1 會標準化為 ±1.5，且賠率只接受 BetExplorer 的 `Stake.com` ±1.5 列。
- 找不到該列時保留前值並標示部分缺漏，不使用 Bet365。
- 整輪網路失敗時不寫出空資料檔。

### 前端測試

- 四個聯盟的比賽可在同一大頁面直接看見 Stake 讓分方、大小分與換邊摘要。
- 自動擁有的讓分方與大小分會隨有效資料更新。
- 人工按對調或編輯大小分後不再被自動覆蓋。
- 「恢復自動」可重新啟用個別欄位同步。
- 過期、部分缺漏與凍結狀態可區分；缺資料時不顯示假賠率。
- 卡片的建立、儲存、跨裝置同步與既有結算功能不回歸。

### 實際驗收

至少以一個有賽程的聯盟完成真實資料演練，確認資料時間新鮮、來源標記正確，並以開賽前最後合格快照驗證三十秒凍結。若當日 MLB 沒有正常賽事，MLB ±1 特例先以固定測試樣本驗證，待出現真實盤口再做第二階段實盤確認。

## 13. 部署安全

- 工作流 YAML 使用無 BOM UTF-8，並在提交前驗證前三個位元組。
- 若新增套件，`package.json` 與 `package-lock.json` 必須同步提交。
- 不提交 repo 根目錄的 `test_*.js` 或測試產物。
- 提交前檢查 staged 檔案，提交後以 `git show --stat` 核對檔數。
- 推送前執行 `git pull --rebase origin main`；爬蟲持續提交期間採併發安全流程。
- 不為部署取消正在執行的 GitHub Actions run。
