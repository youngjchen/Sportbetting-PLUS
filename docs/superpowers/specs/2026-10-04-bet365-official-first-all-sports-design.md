# Bet365 官網優先的全運動賠率管線設計

日期：2026-10-04

## 目標

棒球（MLB／NPB／KBO／CPBL）、籃球（NBA／WNBA）與冰球（NHL）的 Bet365 賠率全部以 Bet365 官網為第一來源。BetExplorer 只在官網暫時缺盤或抓取失敗時備援；Titan 不再參與即時盤口、讓分方或對調警示判定，只保留既有歷史資料用途。

本次改動同時修正中華職棒的錯誤警示：Bet365 官網已有盤時，不得因 BetExplorer 缺少 Bet365 列而顯示「抓不到」。

## 已確認的現況與根因

- 棒球卡片的 Bet365／台彩警示仍以 `data/oddsportal_summary.json` 內 BetExplorer 的 `bet365` 列作現行方向主來源；BetExplorer 漏掉中職時，警示會錯報 Bet365 無資料。
- `bet365_fallback.js` 只支援 MLB，而且只在 Titan 沒盤時補值，並非官網優先。
- `nba_bet365_odds.js` 與 `wnba_titan_odds.js` 的 Bet365 實際來自 Titan companyId=8。
- `nhl_bet365_odds.js` 已直抓 Bet365 官網，但目前聯盟 Hub 只穩定提供獨贏與讓分；大小分必須由官網事件詳情補抓。
- Bet365 公開 Hub 的市場完整度不一致：MLB 可直接看到三盤，NBA Hub 目前只見獨贏，NHL Hub 目前可見獨贏與讓分。因此不能把 Hub 當唯一來源。

## 採用方案

採「共用正規化核心、各運動獨立收集器」。不做每個頁面各自硬補，也不把所有運動塞進單一工作流。

### 共用核心

新增共用 Bet365 核心，負責：

- 正規化獨贏、讓分、大小分。
- 驗證雙邊賠率、正負讓分與主客隊方向。
- 以同一場的主客隊與開賽時間合併不同 market fixture id。
- 記錄來源、觀測時間、歷史與健康狀態。
- 執行開賽前 30 秒凍結。
- 來源切換只記 `source-change`，不記 `favorite-flip`。

### 各運動收集器

- 棒球：`baseball_bet365_odds.js`，涵蓋 MLB／NPB／KBO／CPBL，輸出 `data/baseball_bet365_odds.json`。
- 籃球：保留 `nba_bet365_odds.js` 檔名並改成官網收集器，同時涵蓋 NBA／WNBA；既有 WNBA Titan 檔只留歷史相容。
- 冰球：擴充 `nhl_bet365_odds.js`，在既有 Hub 資料外補抓官網事件詳情的大小分。

三條管線互相隔離；單一運動抓取失敗不得拖垮其他運動。

## 官網抓取流程

每場採兩階段：

1. 從 Bet365 官網聯盟頁／運動頁發現賽事與 Bet365 event id。
2. 用 Bet365 官網事件詳情頁或同源事件資料取得完整三盤。

抓取沿用專案現有 `sidecar_client.js` 與 Scrapling：一般 HTTP 失敗後切隱形瀏覽器，必要時在 Bet365 同源頁面讀事件資料。不得使用第三方來源冒充官網結果。

賽程與主客隊配對以現有官方賽程資料為權威：

- 棒球：`data/pregame_data.json` 與 MLB 官方資料。
- NBA／WNBA：各自的官方／玩運彩賽程檔。
- NHL：`data/nhl_pregame.json` 的官方賽程。

BetExplorer 不負責驗證賽程，也不負責建立卡片。

## 資料優先級

每個市場分開裁決，順序固定為：

1. 開賽前且新鮮的 Bet365 官網資料。
2. 開賽前且新鮮的 BetExplorer Bet365 列。
3. 最後一筆已凍結的 Bet365 官網賽前快照，只供顯示，明確標成舊快照。
4. 無資料。

Titan 不在這個優先級內。

如果同一場只有官網獨贏、BetExplorer 有讓分與大小分，可以逐市場補齊，但 UI 必須在各市場顯示真實來源，不得整場統稱為 Bet365 官網。

## 歷史與對調判定

- 所有歷史列保存 `provider`、`observedAt`、讓分方、讓分線與雙邊賠率。
- 只有同一 provider 連續兩次有效觀測的讓分方不同，才算一次 `favorite-flip`。
- 官網切到 BetExplorer 或 BetExplorer 切回官網，只記來源切換，不算對調。
- 單純從 ±1.5 變 ±1、±4.5 變 ±1.5，只算基準線變動；讓分方沒變就不算對調。
- 開賽前最後 30 秒以及開賽後的任何觀測不得進現行盤、歷史或對調統計。
- 官網與備援各自保留歷史；明細展開時顯示來源，避免把不同來源拼成一條假變盤。

## 卡片與警示行為

- Bet365 官網有盤：顯示官網資料，不再受 BetExplorer 是否有列影響。
- 官網缺該市場但 BetExplorer 有：顯示 `BetExplorer 備援`。
- 兩者都沒有：才顯示 `BET365：目前無盤`。
- 抓取器失敗但有舊快照：顯示數值及 `舊快照 HH:mm`，不得把舊值說成即時盤。
- 警示條的讓分方向、曾對調與歷史明細改讀新的裁決層。
- Stake 管線保持獨立；Stake 與 Bet365 的歷史、對調次數不互相污染。
- 卡片既有手動對調與手動大小分優先權不變。

## 工作流

- 新增棒球 Bet365 官網長迴圈工作流。
- NBA Bet365 工作流改用官網，並納入 WNBA。
- NHL Bet365 工作流擴充大小分。
- 每輪約五分鐘，只 stage 自己的資料檔；失敗時不覆蓋上一份有效資料。
- 看門狗新增或調整三份官網資料檔的新鮮度檢查。
- BetExplorer 工作流保留，但產出只作備援，不再主導警示。
- 所有 workflow YAML 維持無 BOM，`cancel-in-progress: false`。

## 相容與遷移

- 既有 `data/odds_log.json`、`data/wnba_odds_log.json` 與 Titan 歷史不刪除。
- 新管線先讀舊資料作相容顯示，但新觀測一律寫入官網專用資料檔。
- 前端改完後，Titan 只供歷史統計；不得回填現行讓分方或製造對調警示。
- `data/oddsportal_summary.json` 保留給 Stake ±1.5 特例與 Bet365 備援，但不再作 Bet365 即時主來源。

## 測試與驗收

- 解析測試：三種市場、雙邊賠率、主客方向、不同 fixture id 合併、未知隊名、缺邊拒收。
- 凍結測試：開賽前 30 秒後與開賽後觀測均拒收。
- 來源切換測試：官網／BetExplorer 切換不增加對調次數。
- 基準線測試：±1.5→±1 與 ±4.5→±1.5 不算對調。
- 備援測試：官網有盤永遠壓過 BetExplorer；官網缺市場時才逐市場補入。
- 棒球驗收：中職 Bet365 官網有盤時卡片不得顯示抓不到，四聯盟皆可配對。
- 籃球驗收：NBA／WNBA 三盤皆顯示實際來源，不再以 Titan 冒充即時 Bet365。
- NHL 驗收：獨贏、讓分、大小分皆可由官網事件資料取得；缺盤時才使用 BetExplorer。
- UI 驗收：警示條只在同來源真的換邊時顯示對調，詳細歷史列出每筆來源。
- 完成前跑單元測試、整合測試、瀏覽器測試、實站抓取與 YAML/BOM 檢查。
