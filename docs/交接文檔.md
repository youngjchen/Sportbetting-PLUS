## §3 歷史事故與救援 SOP（血淚換來的）

1. **concurrency 死鎖（7/23，停更 4.5h）**：對「執行中」的 run 按取消 → 群組死鎖、佇列永不升格、之後每個 cron 排進去就被 churn。
   **SOP：先取消全部 queued → 再取消 running → 立刻 dispatch。順序錯就死鎖。** 平時根本不要手動碰——PAT 接棒＋看門狗已全自動。
2. **迴圈 wedge（7/17）**：迴圈內先 commit 再 pull --rebase，衝突被 `|| true` 吞掉 → 之後每輪 push 靜默失敗。修法＝每輪開頭 `rebase --abort; fetch; reset --hard origin/main`（兩支爬蟲都已內建；改迴圈時不得退回舊寫法）。
3. **跨午夜三刀（7/23 資料全滅）**：run 內即時重算「今天」跨午夜漂移 → 日期歸屬錯亂＋空頁擦除。修法＝所有日期在 run 啟動點凍結＋空頁防擦除（本輪 0 筆而前輪有單＝不取代）。
4. **BOM 拒收**：見 AGENTS.md §Git 鐵則 5。診斷特徵＝run `conclusion=failure 且 jobs total_count=0`。
5. **npm ci lock 失同步（7/18 起占卜死 9 天）**：改 package.json 沒重生 lock；只有用 `npm ci` 的工作流死、用 `npm install` 的沒事＝故障只打中一部分、更難察覺。
6. **診斷紀律**：停更第一步＝比對「commit 時間軸空窗」與「run 列表」；`jobs total_count=0` 的 run＝從未執行（≠執行失敗）。GitHub API 時間全是 UTC，先 +8 再推理。
7. **四顆漏單雷**（明牌管線史，全是使用者抽查揪出）：①白名單被榜單身分跳過 ②暱稱異體字精確比對 ③清晨場日界 ④名額飢餓。教訓＝資格/名冊/日期的每個篩選都可能靜默漏人，寧可全量。
8. **明牌歸檔曾三天沒上雲**：舊工作流只 `git add` 主檔。新工作流已含歸檔目錄；7/20~7/22 的歸檔永久缺（僅能從 git 歷史撈無結果版）。

## §4 資料檔完整語義

- **`odds_log.json`**：`{matches:{titanId:{awayTeam,homeTeam,startISO,lastUpdated,ml:{bet365:{open,live[]}},hd:{bet365:[rows]},ou}}}`。
  hd row `{home,line,away}`：line **正=主隊讓、負=客隊讓**（用獨贏熱門校準過）；**rows[0]=最新，末端=初盤（prepend！）**；rows 無時戳；`lastUpdated>startISO` 代表含開賽後 30 分寬限窗的**場中盤**——判「收盤」要用開賽前凍結的快照（`odds-integration.js closeHdFor`，`frozen:true` 才可信）。
- **`pregame_data.json`**：陣列；`officialId=LG_YYYYMMDD_AWAY@HOME_HHMM`（台灣時間）；status upcoming/inprogress/finished/postponed；比分、ERA、`lotteryHandicap{favSide,line}`。日韓中職比分權威=此檔；MLB 比分權威=statsapi（板端直連）。
- **`lottery_series.json`**：台彩讓分方時序 `games[officialId].pts[{t,side,line}]`——只記變化點；停更空窗內的「調換又調回」不會留痕（7/23 韓華案）。
- **`expert_picks_{lg}.json`**：`{updated,mode,lastFullAt,lastDeepAt,counts,coverage,lastFinal,qualCache{qual,mainQual,nick,preGamers,firstFetched},picks[]}`。
  picks 欄位：`league,date,time,away,home,market(hd|ml|ou),team,side,line,srcMode,srcLabel,wp,total,main,free,result,uid,nickname,at`。
  akey（唯一鍵/去重/歸檔）＝`uid|league|date|away|home|time|market|(team||side)`——**不含 line**（改線=同注更新）。`at`=首次抓到時刻。`result`（win/lose）只在深掃回溯頁出現後回填。
- **`expert_archive/YYYY-MM-{lg}.json`**＋舊 `YYYY-MM.json`（legacy 家族，7/18-19 有料）：板端讀舊日期一律兩家族＋主檔**聯集**（教訓：任何「來源遷移時刻不同步」的資料都必須聯集，嚴禁 early-return 二選一——7/25 明牌整批消失案）。
- **玩運彩端點**：勝率榜 `/billboard/winRate?allianceid&mode&during&page`（XHR JSON）；主推榜 `/billboard/mainPrediction`；個人頁 `/member/{uid}/prediction?allianceid&gameday=today|tomorrow|yesterday|2daysAgo|3daysAgo|4daysAgo`（**第 5 天起空頁**，指定日期格式無效）；個人戰績 `/member/{uid}/record/winRate`。時間格式陷阱：亞洲場「PM 13:00」=24h 制混 PM 前綴，美東場才是真 12h 制。
- **`state/board_state.json.gz`**：盤面主檔跨裝置同步（gzip 純 JSON doc）。合併=union：上傳 keeper=本機、下載 keeper=雲端。
- **`state/dv_casts.json.gz`**：手動卜卦雲備份（gzip 純 JSON 陣列）；`github-sync.js __dvSync`：起卦後 90s 自動推、開板 4s 自動拉、castKey=`ts|officialId|market|method` union 只增不減。
- **占卜檔**：`liuyao_casts.json`／`qiuqian_casts.json`／`xiaoliuren_casts.json`（機器卦，凍結實驗，命中率遮蔽至 2027 分析日——不要提前開盒）；`qimen_data.json`(untracked 16MB)+`qimen_c1.json`＝神刻奇門，**資料只到 6/26、無排程，待使用者拍板自動化或移除**。
- **手動卦（板上）**：`localStorage['dvManualCasts']`，上限 8000 筆、配額不足降級告警；匯出備份為信封格式 `{__envelope:'sbplus-backup-v1',doc,dvManualCasts}`（匯入自動拆、舊格式相容）。

## §6 使用者協作規範（違反會被罵，全部真實發生過）

1. 繁體中文、**白話**：術語當場解釋；前一則訊息的代號（A/C/E、甲乙丙、Q2…）重提時必須完整展開，不准讓使用者往上滑。
2. **照字面執行**；規格/數值語意不明（且猜錯要重工）時先用純文字問清楚。選項用純文字列，不用選擇元件。
3. 報告先講結論、簡單明瞭、命中率等數字為主；不要冗長儀式。
4. UI：圖標>顏色>文字；點擊不得變形位移；刪去多餘警示與重複資訊（使用者主動要求過多次「拔掉」）。
5. Token 紀律：多代理先算乘法成本；長任務分塊+檢查點；連 3 失敗熔斷停下來想。
6. 收工前必跑驗證拿證據；**不得用「救回/修好」描述未實際驗證的東西**（描述資料復原時要先比對「救回的」與「本來就有的」是不是同一批——踩過）。
7. 每次回覆結尾：①我最沒把握的事 ②使用者可能的最大遺漏。
8. 操作變更告知義務：改了使用者日常流程（如「不要再手動取消 run」「要重新整理頁面」）要明講。
9. `C:\Users\User\.codex` 與 `.cache\codex-runtimes` 絕對禁刪禁動。
